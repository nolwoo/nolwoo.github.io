# 인생책숲 (life.book.forest) 홈페이지 PRD

> 문서 상태: 1차 초안 (2026-08-03)
>
> **자료 출처와 한계**: Instagram 프로필 소개글, 카카오 오픈채팅 링크, 당근 모임 페이지
> (「육아 독서모임 인생책숲」, 봉담읍)의 공개 게시글 14건을 근거로 작성했다.
> 게시글 대부분이 2025년 자료이고 본문을 요약 형태로만 확인했으므로,
> **아래의 기수·일정·참가비·진행자 이름은 확정 정보가 아니다.**
> 8장 「운영자 확정 필요」 표를 채운 뒤에 실제 콘텐츠를 확정한다.

## 1. 개요

- **이름**: 인생책숲
- **한 줄 정의**: 부모의 인생을 공유하는 독서모임 플랫폼
- **소개 문구(현행)**: "책 읽고 소통하며 더불어 살아가는 공동체를 지향합니다"
- **운영자**: '행복지기' (당근 모임장)
- **운영 방식**: 온라인 기반(줌·단톡방) + 봉담 지역 오프라인 모임 병행
- **거점**: 경기도 화성시 봉담읍 내리 (운영자 거주지 기준). 오프라인 모임은 지역 공간을 빌려 진행
- **채널**: Instagram [@life.book.forest](https://www.instagram.com/life.book.forest) (팔로워 약 1,400),
  카카오 오픈채팅 [open.kakao.com/o/gp18A1Nf](https://open.kakao.com/o/gp18A1Nf), 당근 모임

### 하나의숲(one-forest)과의 관계

**운영 주체가 같다.** 저장소의 `one-forest/`(하나의숲 · 구 돌고래상점, 봉담읍 진등2길 13)를
같은 사람이 운영하며, 인생책숲의 오프라인 모임 상당수가 그 공간에서 열린다.
따라서 두 사이트는 **한 브랜드 패밀리**로 다룬다.

- **사이트는 분리한다.** 하나의숲은 "봉담의 오프라인 공간", 인생책숲은
  "온라인 기반 부모 독서모임 플랫폼"으로 대상과 목적이 다르다. 한 사이트에 합치면 둘 다 흐려진다.
- **디자인 언어는 공유한다.** `one-forest/styles.css`의 '필드노트' 토큰
  (`--paper #f1ecdc`, `--ink #2a2b1f`, `--moss #445533`, `--bark #5b4632`, `--honey #c98a2b`,
  본문 Pretendard / 제목 Gowun Batang)을 그대로 가져다 쓰고,
  인생책숲 쪽은 **밤에 읽는 톤**에 맞춰 한 단계 차분하게 조정한다 (9장).
- **상호 링크를 건다.** 하나의숲 `programs.html`의 독서모임 항목 → 인생책숲 모임 상세,
  인생책숲의 오프라인 모임 카드 → 하나의숲 오시는 길. 양쪽 푸터에 서로를 넣는다.
  → 이 작업은 인생책숲 사이트 완성 후 `one-forest/`에도 소폭 수정이 필요하다.

## 2. 문제 정의

지금 인생책숲의 정보는 세 곳에 흩어져 있다.

- **Instagram**: 모집 카드뉴스가 올라오지만 시간이 지나면 피드 아래로 밀려 검색이 안 된다
- **당근 모임**: 지역(봉담) 사용자에게만 노출되고, 온라인 모임 참여자에게는 닿지 않는다
- **카카오 오픈채팅**: 이미 들어온 사람만 볼 수 있다

그래서 처음 관심을 가진 부모는 이런 질문에 한 번에 답을 얻지 못한다.

- 지금 신청할 수 있는 모임이 뭐가 있지?
- 이 모임은 온라인인가 오프라인인가, 몇 시에 하나?
- 참가비는 얼마고, 못 나가면 환불이 되나?
- 나 같은 사람(육아 중, 초보, 완독 자신 없음)이 껴도 되나?

홈페이지는 Instagram을 대체하지 않는다. **Instagram·당근에서 유입된 사람이
"지금 모집 중인 모임"을 한 화면에서 보고 오픈채팅 입장까지 가도록 만드는 공식 안내 허브**다.

## 3. 목표 우선순위

1. **모집 중인 모임 안내** (최우선) — 무엇을, 언제, 얼마에, 어떻게 신청하는지
2. **모임 종류 소개** (최우선) — 독서·필사·운동인증·등산·수공예 등 상시 라인업의 성격
3. **커뮤니티 소개 & 신뢰 형성** — 운영 철학, 운영 기간, 참여자 후기
4. **문의 경로 통합** — 오픈채팅 / 인스타 DM

비목표는 10장 참고.

## 4. 핵심 사용자

1. **육아 중인 부모 (주 타깃)** — 30~40대, 아이 재우고 밤 9시 반 이후에 시간이 나는 사람.
   모바일로 본다. "부담 없이 낄 수 있나"를 가장 궁금해한다.
2. **봉담·화성 지역 주민** — 당근에서 보고 오프라인 모임을 찾는 사람. 장소와 요일이 중요하다.
3. **Instagram 유입 방문자** — 카드뉴스를 보고 링크를 눌러 들어오는 사람. 전체 라인업과 신뢰 근거를 본다.
4. **기존 회원** — 다음 기수 일정과 이번 달 지정도서를 확인하러 온다.

## 5. 대표 사용자 흐름

### 신규 신청자 (주 흐름)

`Instagram/당근 유입 → 홈 → "지금 모집 중" 카드 → 모임 상세(일정·참가비·환불) → 오픈채팅 입장 → 운영자 안내`

### 처음 보는 사람

`홈 → 인생책숲이 뭔지 한 문단 → 모임 종류 훑기 → 후기 → 오픈채팅 or 인스타 팔로우`

### 기존 회원

`홈 → 모임 일정 → 이번 기수 지정도서·모임 날짜 확인`

## 6. 사이트 구조

`nolwoo.github.io/book-forest/` 하위 정적 HTML. **3장으로 시작한다.**

| 파일 | 페이지 | 핵심 내용 |
|---|---|---|
| `index.html` | 홈 | 히어로(슬로건), 인생책숲 소개 한 문단, **지금 모집 중인 모임 카드 목록**, 모임 종류 요약, 후기, 오픈채팅 CTA |
| `programs.html` | 모임 안내 | 모임 유형별 상세(성격·진행 방식·대상·보통 참가비), 전체 모임 목록(모집중/진행중/마감 필터), 참가·환불 규정 |
| `about.html` | 인생책숲 소개 | 운영 철학, 운영자 소개, 운영 기록(기수 누적), 후기 모음, 문의 경로 |

공통 헤더(로고 + 3개 메뉴 + 오픈채팅 버튼)와 푸터(인스타·오픈채팅·당근 링크)로 연결.

> 페이지를 4장이 아니라 3장으로 잡은 이유: 온라인 기반 플랫폼이라 "오시는 길" 전용 페이지가
> 필요 없다. 오프라인 모임은 회차마다 장소가 달라지므로 모임 카드 안에 장소를 적는 편이 정확하다.

### 페이지별 CTA

| 페이지 | 주 CTA | 보조 CTA |
|---|---|---|
| 홈 | **오픈채팅 입장하기** | 모임 전체 보기, Instagram |
| 모임 안내 | **이 모임 신청 문의(오픈채팅)** | Instagram DM |
| 소개 | **오픈채팅 입장하기** | Instagram 팔로우 |

**주 CTA는 카카오 오픈채팅이다.** 현재 실제로 작동하는 유입 경로가 오픈채팅 링크와 당근 댓글이므로,
운영자가 이미 익숙한 경로를 그대로 웹으로 옮긴다. 별도 신청 폼(Formspree 등)은 필수가 아니며,
운영자가 "채팅 말고 폼으로 받고 싶다"고 할 때만 추가한다 (9장 확장 항목).

## 7. 핵심 요구사항 — 모임 데이터 분리 (이 프로젝트에서 제일 중요한 부분)

인생책숲은 **기수제(期數制) 모임 플랫폼**이다. 오롯이 13기, 쓰는독서 6기, 운동인증 3기처럼
같은 모임이 1~3개월마다 새 기수로 다시 모집된다. 즉 **홈페이지 내용은 매달 바뀐다.**

만든 HTML에 일정을 직접 적어두면, 다음 달이면 낡은 사이트가 된다.
운영자가 개발자가 아니므로 "HTML을 열어서 태그 사이 글자를 고친다"는 방식은 실패한다.

### 해결 방식

이 저장소의 `dashboard/`, `kids-photos/`가 이미 쓰는 패턴을 따른다 —
**콘텐츠를 데이터 파일 하나에 모으고, HTML은 그걸 읽어서 그린다.**

```
book-forest/
  index.html
  programs.html
  about.html
  data/
    programs.js   ← 운영자가 고치는 파일은 여기 하나뿐
  styles.css
  script.js
```

`data/programs.js`는 모임 하나당 객체 하나인 배열이다.

```js
const PROGRAMS = [
  {
    id: "orosi-14",
    type: "독서모임",              // 독서모임 | 필사 | 운동인증 | 등산 | 수공예 | 일회성
    name: "오롯이",
    cohort: "14기",
    status: "모집중",              // 모집중 | 모집마감 | 진행중 | 종료
    mode: "온라인",                // 온라인 | 오프라인
    place: "줌",                   // 오프라인이면 장소명
    schedule: "매주 월요일 21:30~23:00",
    period: "2026-09-01 ~ 2026-11-30 (12회)",
    deadline: "2026-08-25",
    capacity: "4~6명",
    fee: "60,000원 (12회 전체)",
    host: "행복지기",
    books: ["9월 지정도서 …", "10월 지정도서 …"],
    summary: "한 달에 한 권 지정도서, 나머지 주는 각자 고른 책을 돌아가며 발제합니다.",
    applyUrl: "https://open.kakao.com/o/gp18A1Nf"
  },
  // …
];
```

- 홈은 `status === "모집중"`인 항목만 카드로 뽑아 보여준다.
  하나도 없으면 "지금은 모집 중인 모임이 없어요. 오픈채팅에서 다음 모집 소식을 받아보세요" 안내를 띄운다.
- 모임 안내 페이지는 전체를 상태별로 묶어 보여준다. 지난 기수는 **운영 기록**으로 남아
  "5년째, 14기까지 이어온 모임"이라는 신뢰 근거가 된다.
- 후기도 같은 방식으로 `data/reviews.js`에 분리한다.

### 운영자용 수정 가이드 (확정: 운영자가 직접 수정)

운영자가 `data/programs.js`를 직접 고치는 방식으로 확정했다.
구글 시트 연동은 쓰지 않는다 — 외부 의존과 로딩 단계가 늘고, 시트 공개 설정이 또 하나의 실패 지점이 된다.

이 방식이 성립하려면 **파일 자체가 문서 역할을 해야 한다.** 지켜야 할 것:

- 파일 맨 위에 주석으로 작성 규칙을 적는다 — `status`에 쓸 수 있는 값,
  날짜 형식, 지우면 안 되는 항목.
- 새 기수를 만들 때 복사해 쓸 **템플릿 블록**을 파일 하단에 주석 처리해 남겨둔다.
- 항목명은 한글 주석을 곁들여, 값만 봐도 어디에 나오는지 알 수 있게 한다.
- 값이 비었거나 오타가 나도 페이지 전체가 깨지지 않게 렌더링 쪽에서 방어한다
  (없는 항목은 그냥 안 보이게). **비개발자가 고치는 파일이므로 깨짐은 예정된 일이다.**
- `book-forest/README.md`에 **"새 기수 올리는 법"**을 단계별로 적는다:
  GitHub 웹에서 `data/programs.js` 열기 → 템플릿 블록 복사 → 값 수정 →
  `status: "모집중"` 확인 → 커밋 → 몇 분 뒤 사이트 반영. 지난 기수는 지우지 말고
  `status`만 `"종료"`로 바꾼다(운영 기록으로 남는다)는 점을 명시한다.

## 8. 모임 라인업 (구조 정의 — 실제 값은 운영자 확정 필요)

당근 게시글에서 확인된 모임 유형이다. **참가비·주기는 관찰된 범위일 뿐 확정값이 아니다.**

| 유형 | 예시 이름 | 성격 | 관찰된 주기 | 관찰된 참가비대 |
|---|---|---|---|---|
| 정기 독서모임 | 오롯이 | 3개월 12회, 밤 9시 반 온라인, 4~6명 | 분기마다 새 기수 | 6만원대(전 회차) |
| 필사모임 | 쓰는독서 | 4주간 매일 한 문장 필사 + 온라인 모임 2회 | 수시 | 2만원대 |
| 습관·인증모임 | 운동인증 | 3주 평일 인증, 완주 시 일부 환급 | 수시 | 2만원대(일부 환급) |
| 일회성 북토크 | 기후여행자, 원미동 사람들 등 | 특정 책 1권, 오프라인 저녁, 소수 | 비정기 | 무료~1.5만원 |
| 취미모임 | 등산, 뜨개질·수공예 | 부모 대상 오프라인 활동 | 격월~비정기 | 1만원대(공간비) |

> ⚠️ **명칭 대조 필요.** 위 표는 당근 게시글(대부분 2025년)에서 뽑은 이름이다.
> 반면 2026년 7월 Instagram에서 관찰된 현행 명칭은
> **다독홀께 · 벽돌책깨우기 · 필사 · 포미프로젝트**다.
> '필사'는 쓰는독서, '포미프로젝트'는 수공예에 대응할 가능성이 있지만,
> **다독홀께와 벽돌책깨우기는 위 표에 없는 모임**이다.
> 어느 이름이 현재 쓰는 이름인지 운영자에게 확인한 뒤 라인업을 확정한다 —
> 중단된 모임 이름을 사이트에 박아두는 일을 막는 지점이다.

### 모임 카드에 반드시 들어갈 항목

일정 / 온·오프라인 / 장소 / 정원 / 참가비 / 신청 마감 / 진행자 / 지정도서 / **환불 규정**

### 참가비와 환불 (필수 고지)

- 정적 사이트라 **온라인 결제(PG)는 없다.** 참가비는 오픈채팅에서 계좌 안내 후 이체받는 방식으로 안내한다.
- 계좌번호는 웹에 공개하지 않고 "신청 확정 시 오픈채팅으로 안내"로 표기한다.
- 당근 게시글에 이미 공개된 환불 기준(시작 1주 전 전액 환불 / 단톡방 개설 후 환불 불가 등)은
  **사이트에도 동일하게 명시한다.** 이미 공개적으로 약속한 내용이고, 유료 모임에서 분쟁을 막는 최소 장치다.
- 정확한 문구는 운영자가 확정한다 (8-1 표).

**금액 공개 여부는 미확정이다.** 운영자 확인 후 결정한다. 다만 어느 쪽으로 정해지든
`data/programs.js`의 `fee` 값 하나만 `"60,000원"` ↔ `"유료 (오픈채팅 문의)"`로 바꾸면 되도록
만들어, 나중에 방침이 바뀌어도 다시 개발하지 않는다.

## 9. 디자인 톤

- **하나의숲과 같은 디자인 언어**를 쓴다. `one-forest/styles.css`의 토큰과 폰트를 가져와
  자매 사이트임이 한눈에 보이게 한다 (1장 참고).
- **다만 무드는 한 단계 차분하게.** 하나의숲이 낮의 오프라인 공간이라면,
  인생책숲은 아이 재우고 밤 9시 반에 책상 앞에 앉는 사람들의 모임이다.
  `--honey` 같은 포인트 색은 CTA에만 쓰고, 손글씨체(Gaegu)는 쓰지 않거나 최소한으로 쓴다.
- 팔레트 기준: `--paper` 배경 + `--ink` 본문 + `--moss` 강조 + `--honey` CTA.
  자극적인 색이나 마케팅 느낌은 피한다.
- 타이포 중심 디자인이 기본이나, 실제로는 인스타그램에서 가져온 실제 사진 3장으로
  히어로·스냅샷 갤러리를 구성했다 (해상도가 낮아 원본 교체 권장 — 8-1장 참고).
  사진이 부족하거나 교체되기 전에도 **글이 잘 읽히는 것**이 항상 우선이다.
  본문 한글 가독성(자간·행간)을 우선한다.
- 이모지는 절제해서 쓴다 (📚🌿 정도). 인스타 톤과 이어지되 웹에서는 한 단계 차분하게.
- 모바일 우선. 실제 방문자는 거의 다 휴대폰이다.
- 한글 줄바꿈: 조사·접속사가 줄 끝에 홀로 남지 않게 끊는다.

## 10. 기술 스택 / 비기능 요구사항

- 순수 HTML/CSS/JS, 빌드 없음. 저장소의 다른 정적 앱과 같은 패턴
- 콘텐츠는 `data/programs.js`, `data/reviews.js`로 분리 (7장)
- 로그인·개인정보 저장 없음
- 배포: `git push` → GitHub Pages (`nolwoo.github.io/book-forest/`)
- 반응형: 360px~1440px에서 레이아웃 유지, 가로 스크롤 없음
- 접근성: 색 대비, 이미지 대체 텍스트, 키보드 포커스, 의미 있는 링크 문구
- 성능: 이미지 lazy-loading, 외부 스크립트 최소화
- SEO: 페이지별 title/description, Open Graph 태그.
  **검색 노출 목표 키워드**: "육아 독서모임", "엄마 독서모임", "온라인 독서모임", "봉담 독서모임", "필사모임"
- 외부 서비스(오픈채팅·인스타)가 안 열려도 모임 정보 자체는 사이트에서 읽힌다

## 11. 성공 지표 (MVP)

- 홈 첫 화면에서 "지금 모집 중인 모임"이 보이고, 3탭 안에 오픈채팅으로 넘어간다
- 운영자가 개발자 도움 없이 새 기수를 혼자 등록한다 (README 보고 10분 내)
- 모집 중인 모임이 없을 때도 사이트가 빈 화면이 아니라 안내를 보여준다
- 모바일에서 참가비·환불 규정을 스크롤 한 번에 확인할 수 있다

## 12. MVP 수용 기준

- [ ] 홈에서 인생책숲의 정체성과 모집 중인 모임을 확인할 수 있다
- [ ] 모임 카드에 일정·형태·정원·참가비·마감·환불 규정이 모두 표시된다
- [ ] 모임 안내 페이지에서 모집중/진행중/종료를 구분해 볼 수 있다
- [ ] 지난 기수 기록이 남아 운영 이력이 드러난다
- [ ] 모든 페이지에서 오픈채팅 CTA에 닿을 수 있다
- [ ] `data/programs.js`만 고쳐도 모든 페이지 내용이 갱신된다
- [ ] 모집 중인 모임이 0건일 때의 화면이 정의되어 있다
- [ ] README에 "새 기수 올리는 법"이 비개발자 기준으로 적혀 있다
- [ ] `data/programs.js`에 작성 규칙 주석과 복사용 템플릿 블록이 들어 있다
- [ ] 항목 값이 비어 있어도 페이지가 깨지지 않는다
- [ ] 오프라인 모임 안내에서 하나의숲(one-forest) 사이트로 연결된다
- [ ] 360px~1440px에서 레이아웃이 깨지지 않는다
